## 0. Motivation (from v4 and the v4 post-hoc exploratory analysis)

| v4 observation | v5 response |
|---|---|

## 1. Fixed serving configuration (identical across every cell and its control)

- **Model and engine:** vLLM 0.17.1, Qwen2.5-7B-Instruct, RTX 3090, max_model_len 4096, prefix caching on, chunked
  prefill on, gpu_memory_utilization 0.8.
  - These were recorded by v4. The model revision and launch flags are **still not host-verified**; that is gate P1.
- **Server and gateway:** one vLLM server start per stage (gate). FCFS gateway, 60 s queue timeout.
- **Requests:** real-token prompts (`prompt_token_unit: tokenizer`) and `ignore_eos: true`.
- **Victims:** exactly as in v4. Three tenants at 0.3 rps each, 64-token output, user-facing TTFT SLO 2 s, E2E SLO
  30 s.
- **The only serving parameter that varies is the gateway cap C** (`safety.max_global_inflight`).
  - It is a between-block factor, identical in each block's attack and control arms. `build_v5.py` and the tests
    enforce this: files of one cell differ only in id, salt, header and cap.
  - Direct-vLLM files carry C = 8 for schema identity, but no gateway is applied.
- **Token quota:** the per-tenant token ledger quota is `C × max per-request tokens`, so it never binds. It is recorded
  in every manifest.

## 2. Design

| Factor | Levels |
|---|---|
| Gateway cap C | 8, 16, 32; plus **direct vLLM** (no gateway) as a reference path |
| Comparison | **D vs S**: decode 64/256 ×75 vs `token_matched_fixed` short 64/64 ×188 at L = 200. **P vs S**: prefill 1024/32 ×23 vs short ×190. **A/A-ind**: short ×188 vs an independent short ×188 draw |
| Load L (authorized competitor tok/s) | **200** (v4 L\*), Stage A: all three comparisons. **400**, Stage B: D vs S and A/A-ind only |
| Seeds | **10 per cell, 5000–5009**, disjoint from v4 (42–46, 900, 1000). Each seed fixes the victim and competitor schedules; the same schedule is replayed at every C and on the direct path (crossed, paired within seed; enforced by a test over `FROZEN_SCHEDULE.json`) |

- **Arrivals** follow the v4 mechanisms: fixed-count, i.i.d. uniform over 120 s; a `token_matched_fixed` control; and
  the arrival-coverage gate. The offline freeze shows every gate passing on all 23 scenarios.
- **Victim traces** are identical between the attack and control arms of a seed.

## 3. Hypotheses

Confirmatory family **F1 = {H1, H2a, H2b}**, Holm at α = 0.05. Family **F2 = H6** at the three caps, Holm at α = 0.05.
H3, H4 and H5 use their own frozen criteria. H7 is descriptive. Every rule is implemented in `scripts/v5_analysis.py`
and unit-tested on synthetic inputs. In the rules below, ℓ is the per-seed log ratio of victim mean user-facing TTFT,
attack over control, with n = 10.

### 3.1 H1 — replication at C = 8, L = 200 (D vs S)
- **Test:** one-sided t-test of mean ℓ > log 1.25 (`p_superiority`).
- **SUPPORTED** iff Holm rejects within F1. The cell classification (`classify_cell`) is also reported.
- **Prediction:** supported. In v4 the mean ratio was 1.80 (post-hoc), above 1 in 5/5 seeds.

### 3.2 H2a and H2b — two separate hypotheses

These are separate hypotheses with separate tests. Both, either or neither may hold.

**H2a: cap dose-response.**
- **Claim:** the D-vs-S amplification decreases as C increases.
- **Statistic:** for each seed, the OLS slope b_s of ℓ on log2(C) over C ∈ {8, 16, 32}. Seeds are paired across caps.
- **Test:**
  - one-sided t-test of mean(b_s) < 0, giving p_t;
  - exact sign-flip permutation, 2^10 = 1024 sign vectors, one-sided, giving p_perm;
  - p_H2a = max(p_t, p_perm).
- **SUPPORTED** iff Holm rejects within F1.
- **Reported:** mean slope and 95% CI as the ratio change per doubling of C.
- **Evaluable only if** all three D-vs-S gateway cells are in stratum **E∧Vb** (§4). Otherwise "not evaluable"; no
  seeds or caps are dropped.

**H2b: equivalence at C = 32.**
- **Claim:** at C = 32, D vs S is equivalent to no effect within the band [0.8, 1.25].
- **Test:** TOST on mean ℓ at C = 32: p_TOST = max of the two one-sided p values against log 0.8 and log 1.25.
- **EQUIVALENT** iff Holm rejects within F1 **and** the threshold is above noise at C = 32: log 1.25 > 2 × the A/A-ind
  95% half-width.
- **NOT EQUIVALENT** iff the 95% CI lies entirely outside the band. Otherwise **INCONCLUSIVE**, or
  **THRESHOLD NOT ABOVE NOISE**.

**Interpretation matrix.**

| H2a \ H2b | Equivalent at C = 32 | Not equivalent or inconclusive |
|---|---|---|
| **Supported** | amplification is cap-driven and vanishes by C = 32 | amplification shrinks with C but persists at C = 32 |
| **Not supported** | no measurable trend; small effect at every C, or a step change below C = 16 | no cap dependence detected |

- **The C = 32 equivalence is not a blind prediction.** v4 R3 direct runs, observed before this draft, had a
  non-binding cap with maximum concurrency 9–14, which is effectively C ≥ 16. They gave 0.996 [0.958, 1.026] (P95) and a
  mean ratio of 1.07 (post-hoc).
- **So H2b is a pre-registered replication** of that observation through the gateway at a non-binding cap. It is not a
  novel prediction. §3.4 has the leakage audit.

### 3.3 H3 — frozen quantitative FCFS predictions (`experiments/v5/FCFS_PREDICTIONS.json`)

**Model (an estimate):**
- **Arrivals:** the exact v5 schedule of each (cell, arm, seed).
- **Service:** a per-request gateway slot hold [t_sent, t_terminal), resampled with replacement per class (victim or
  competitor) from a **v4 C = 8 gateway** hold pool for the matching (shape, load, arm).
- **Discipline:** a single global FCFS queue with C slots.
- **Monte Carlo:** 200 draws, fixed seed.
- **Outputs, per (cell, arm, seed):**
  - victim mean, P95 and the fraction of victims with gateway queue > 500 ms;
  - fraction of time at C/C;
  - 90% predictive intervals for each.

**Tolerances**, derived only from v4 C = 8 data (leave-one-seed-out on the 30 R1 L = 200 arms; see the table below):
- **Per seed:** |obs − pred| ≤ max(τ_abs, ρ·pred), where τ_abs = **7.05 ms** (q95 |LOSO error|, floor 5 ms) and
  ρ = **0.349** (q95 relative error, obs ≥ 5 ms).
- **Per cell (10-seed mean):** |mean obs − mean pred| ≤ max(5 ms, ρ·mean pred).
- **PASS** for a (cell, arm) iff the cell rule holds and ≥ 8/10 seeds meet the seed rule. The prediction-error metrics
  reported are MAE, signed bias, RMSE and seeds within tolerance (`score_fcfs`).
- **Envelope:** cells at L = 400, or with a predicted mean above the LOSO range (0–192 ms), are scored but labelled
  **extrapolated** and excluded from the H3 verdict. The L = 400 pools come from a single v4 calibration seed (1000).
- **H3 SUPPORTED** iff every in-envelope (cell, arm) at C ∈ {16, 32} passes. The C = 8 cells are scored as the
  predictor's own calibration on v5 traces. If they fail, H3 is reported as "model not calibrated on v5" whatever the
  C ≥ 16 result.

**LOSO validation at C = 8 (v4 data only):**

| n runs | MAE | Bias | RMSE | q95 abs error | q95 relative error (obs ≥ 5 ms) | 90% PI coverage |
|---|---|---|---|---|---|---|
| 30 | 2.2 ms | −2.2 ms | 3.7 ms | 7.05 ms | 0.349 | 0.57 |

- **Disclosure.** The tolerance *rule* was first written with a fixed 7 ms band and a PI-coverage criterion of ≥ 0.7.
  After the LOSO run (v4 data only), and before any v5 data:
  - a relative component was added, because a fixed 7 ms band is meaningless for the 3.9 s cell;
  - PI coverage was made descriptive, because the interval reflects hold-resampling variance only.

**Frozen predictions** (10-seed means of the victim mean gateway queue; full per-seed values are in the JSON):

| Cell | C = 8 attack / control | C = 16 attack / control | C = 32 attack / control | Envelope |
|---|---|---|---|---|
| D vs S, L200 | **56.8** / 3.0 ms (4.7% of attack victims > 500 ms; 10.8% of time at cap) | 0.0 / 0.0 | 0.0 / 0.0 | validated |
| P vs S, L200 | 0.0 / 3.4 | 0.0 / 0.0 | 0.0 / 0.0 | validated |
| A/A-ind, L200 | 7.9 / 3.1 | 0.0 / 0.0 | 0.0 / 0.0 | validated |
| D vs S, L400 | **3,895** / 99.8 (82% of attack victims > 500 ms) | 2.2 / 0.0 | 0.0 / 0.0 | extrapolated |
| A/A-ind, L400 | 99.8 / 100.8 | 0.0 / 0.0 | 0.0 / 0.0 | extrapolated |

**What H3 can and cannot show.**
- At C ≥ 16 and L = 200, the falsifiable content is "gateway queueing vanishes": predicted 0.0 ms, so it is rejected
  if the observed mean exceeds 5 ms.
- If victims' user TTFT still rises at C ≥ 16, the rise must come from backend TTFT, meaning engine batching. That
  relocation is H4.

### 3.5 Limitations of transferring slot-hold durations between caps (review item 5)

1. **Holds are not cap-invariant.**
   - A C = 8 hold is the service time with at most 8 requests co-batched. At C = 16 or 32, more sequences share each
     decode step, so per-request holds lengthen.
   - Longer holds raise occupancy, so the predictions are **biased low**: optimistic about queueing.
   - The magnitude can't be estimated without target-cap data (§3.4).
2. **Resampling holds independently breaks dependence.**
   - In reality, long holds cluster in time (co-batched decode bursts) and correlate with saturation episodes.
   - Independent resampling smooths bursts, which **underestimates tails**. The LOSO results are consistent with this:
     bias −2.2 ms, under-prediction in 23 of 30 runs (4 exact, 3 over), and PI coverage 0.57.
3. **Holds depend on what else is running.**
   - Pools are conditioned on (shape, load, arm), but not on the instantaneous mix.
   - The L = 400 pools come from one calibration seed, in cells that were over the saturation limit at C = 8. Hence they
     are labelled extrapolated.
4. **Slot release is client-observed.** `t_terminal` is the client's terminal timestamp. The gateway's internal
   release can differ by the scrape offset (about 0.15 s) at most in sampled telemetry. Requests are rebuilt from
   client timestamps.
5. **Holds include more than engine service.** They include engine queue (≈ 0 in v4, §5.2), prefill, decode and
   response streaming, so they are not pure GPU time.
6. **Direction of the overall error at C ≥ 16.** Every bias above points toward *more* queueing than predicted. A
   predicted 0 that holds up is informative; a failure tells us hold inflation reached the cap.

### 3.6 H4–H7

**H4: relocation.** For D vs S at L = 200, as C rises:
- **(a)** the attack-arm victim mean backend TTFT at C = 32 exceeds that at C = 8. One-sided paired t-test on per-seed
  log ratios, α = 0.05.
- **(b)** the attack-arm victim mean gateway queue falls, as scored by H3.
- **(c)** the engine queue stays negligible by the §5.2 criterion in every D-vs-S arm at every C: engine-global
  histogram mean ≤ 10 ms **and** every observation in the le = 0.3 s bucket.
- The v4 P95 ≤ 10 ms criterion is **withdrawn**: P95 is not identifiable from these buckets.

**H5: explanatory.**
- Across all v5 gateway arms, victim mean gateway queue has Spearman ρ ≥ 0.6 with (a) the fraction of time at C/C and
  (b) the fraction of victims arriving during saturation, each computed by the frozen slot-time code.
- The v4 exploratory values (0.88, 0.92) are **not** pooled.

**H6: negative control on shape.** P vs S is **equivalent** (TOST, band [0.8, 1.25]) at each C. Family F2, Holm across
the three caps.

**H7: feasibility (descriptive).**
- For every (comparison, C, L), report the stratum (E∧Vb, E∧¬Vb, ¬E) and the attack-arm SLO degradation (§4.3).
- **Pre-registered expectations** follow from H3; they are not tests:
  - at L = 400 and C = 8, attack-arm victim SLO success falls sharply (predicted 82% of victims with gateway queue
    > 500 ms);
  - at C ≥ 16, it does not.

## 4. Feasibility and outcomes (review item 3)

1. **Execution feasibility (E)**, per seed.
   - Every fail-severity integrity gate passes.
   - Competitor completion is ≥ 0.95 **and** victim censoring is ≤ 0.05 in **both** arms.
2. **Baseline victim-SLO feasibility (Vb)**, per seed.
   - The **control arm's** victim offered-load SLO success is ≥ 0.95.
   - This qualifies the *operating point*: the unattacked baseline must already be acceptable to victims.
   - **It never uses the attack arm.** It was called "victim-SLO feasibility" in rev 1.
3. **Attack-arm SLO degradation is an outcome, never a criterion.**
   - It is reported for every cell as the per-seed paired difference (attack − control) in victim offered-load SLO
     success, with mean and 95% t CI (`attack_slo_degradation`).
   - A collapse in attack-arm SLO success is a *finding*. It never invalidates or reclassifies a cell.
4. **Strata, per cell** (`stratum`):

   | Stratum | Condition | Use |
   |---|---|---|
   | **E∧Vb** | every seed E and every seed Vb | primary |
   | **E∧¬Vb** | every seed E, some seed not Vb | reported separately as "victim-overloaded baseline", never pooled |
   | **¬E** | any seed not E | the cell is invalid |

   No seeds are dropped.

### 5.2 vLLM engine histogram semantics (review item 6)

Verified from the vLLM **v0.17.1** source:
- `vllm/v1/metrics/stats.py`
- `vllm/v1/metrics/loggers.py`
- `vllm/v1/engine/output_processor.py`
- `vllm/v1/engine/__init__.py`
- `vllm/v1/core/sched/scheduler.py`

Parts of `loggers.py` and `scheduler.py` were read in summary only. Points marked † are unverified.

| Property | `vllm:request_queue_time_seconds` |
|---|---|
| Definition | `scheduled_ts − queued_ts`: from the engine-core QUEUED event to the **first** SCHEDULED event (`if req_stats.scheduled_ts == 0.0: # ignore preemptions`). Both timestamps are engine-core monotonic |
| Re-queueing after preemption | **excluded**; it is counted inside prefill or decode time |
| Before the engine core | frontend processing, tokenization and IPC are **excluded** |
| When observed | **only when a request finishes** (`update_from_finished_request`) |
| Aborted or cancelled requests | **never observed** (`abort_requests` pops the state without updating stats), including requests aborted while still waiting |
| Labels | `model_name` and `engine` only. **No per-request or per-tenant labels** |
| Buckets | `[0.3, 0.5, 0.8, 1, 1.5, 2, 2.5, 5, 10, 15, 20, 30, 40, 50, 60, 120, 240, 480, 960, 1920, 7680, +Inf]` s. Also confirmed in the v4 `/metrics` snapshots |
| Edge case † | a request finishing without ever being scheduled would record a negative value (code reading only) |

Other histograms:
- **Prefill** (`first_token_ts − scheduled_ts`), **decode** (`last_token_ts − first_token_ts`) and **inference**
  (`last_token_ts − scheduled_ts`): finish-only, same buckets, preemption time included.
- **`time_to_first_token_seconds`:** measured from the **frontend arrival time** to the frontend iteration timestamp
  that processes the first token. It is observed per iteration, not at finish. Its buckets start at 1 ms.
- **Scheduler configuration:** the only `*_info` gauge is `cache_config_info`. **`max_num_seqs` and
  `max_num_batched_tokens` are not exposed** through `/metrics`, so `engine_headroom` needs the host's launch command.

**Interpretation rules for v5:**
1. **No per-request engine queue.** The histogram cannot be read as per-request or per-victim queueing. A per-arm delta
   is an **engine-global aggregate over the requests that finished in the window**, from every tenant, victims and
   competitors mixed.
2. **Sum/count gives an exact engine-global mean.** Buckets give only a coarse distribution with ≥ 0.3 s resolution.
   A millisecond-scale P95 is **not identifiable**.
3. **Selection bias under overload.** Aborted requests are not observed, so the histogram under-represents exactly the
   requests most likely to have waited. Every engine-queue figure is reported beside the censoring count.
4. **v4 evidence (measured, engine-global).** In every v4 R1 and R3 arm, the histogram mean is ≤ 0.012 ms. The
   prefill-heavy attack arms are highest (about 0.011 ms); every other arm is about 0.004 ms. All observations fall in
   the ≤ 0.3 s bucket. So in v4 R1 the engine queue was negligible on both paths, and the gateway-vs-direct difference
   is not engine queueing.
   - This **corrects** a rev 1 / `KNOWN_LIMITATIONS` statement that v4 did not capture the histogram. v4 captured
     sum/count deltas, but not bucket deltas.
5. **Per-victim engine-side decomposition, as an estimate.** Backend TTFT = t_first_token − t_sent is measured per
   request at the client, and it includes engine queue + prefill + streaming.
   - Per-request engine queueing is **unavailable**.
   - vLLM's optional request tracing could provide it, but it would change the launch flags and is not adopted (†: not
     verified for 0.17.1).

## 6. Endpoints and statistical analysis (`scripts/v5_analysis.py`)

- **Primary (every comparison × C × L):** the per-seed victim **mean user-facing TTFT** ratio, attack over control
  (`degradation_metric: user_ttft_mean`).
  - **Estimand:** the mean of the per-seed log ratios.
  - **Interval:** 95% t interval with n = 10 (exact t quantiles implemented and tested). A BCa bootstrap is a
    sensitivity analysis.
  - **Classification** (`classify_cell`):
    - **supported increase:** 95% CI lower bound > log 1.25;
    - **supported decrease:** upper bound < log 0.8;
    - **equivalent:** 90% CI inside the band;
    - otherwise **inconclusive**.
  - **Threshold validity:** 1.25 counts only if log 1.25 > 2× the A/A-ind 95% half-width at the same (C, L). Otherwise
    the cell is flagged "threshold not above noise".
- **Multiplicity:**
  - **F1 = {H1, H2a, H2b}**, Holm at α = 0.05 (`holm`).
  - **F2 = H6** at C = 8, 16, 32, Holm at α = 0.05.
  - H3, H4 and H5 use their own frozen criteria; everything else is descriptive.
- **Secondary, reported for every cell:**
  - victim P95 user-facing TTFT ratio (continuity with v4);
  - tail mass: difference in the fraction of victims with user TTFT > 500 ms and > 2 s;
  - victim SLO success per arm, and **attack-arm SLO degradation** (§4.3);
  - gateway-queue mean and P95;
  - backend TTFT mean and P95;
  - engine-histogram mean and bucket shares (§5.2 caveats);
  - TPOT;
  - competitor slot-seconds per 1k tokens, time fraction at C/C, saturation episodes, and victims arriving during
    saturation;
  - GPU dynamic energy per realized token.
- **Reporting rules:**
  - **No seed exclusion.**
  - **No interim looks:** primary endpoints are not inspected until a stage is complete; only gates are monitored
    during runs.
  - **Post-hoc labels:** every analysis not in this section is labelled post-hoc exploratory.
- **Power** (planning, from v4 per-seed SDs of the mean ratio):

  | Comparison | Log SD | SE at n = 10 | What it can detect |
  |---|---|---|---|
  | D vs S | 0.34 | 0.11 | > 99% power for the v4 effect (log 1.80 = 0.59); about 50% if the true effect were exactly 1.25× |
  | P vs S | 0.14 | 0.044 | equivalence at ±log 1.25 is well powered |
  | A/A | 0.19 | 0.059 | — |

  - **H2a:** with log2(C) at 3, 4, 5, the per-seed slope is (ℓ₃₂ − ℓ₈)/2. With SD 0.34 at C = 8 and an assumed ≤ 0.1
    at C = 32, the slope SD is about 0.18 and SE about 0.056. If the effect goes from log 1.8 to 0, the expected slope
    is about −0.29, so power is high.

## 8. Stopping rules

1. **Pre-stage.**
   - Without host verification of the model revision and launch flags, v5 does not start, unless the owner gives a
     written waiver.
   - If `max_num_seqs` < 64, the C = 32 cells are dropped **before** the freeze, never after.
2. **Integrity failure.**
   - Any fail-severity gate failure stops the stage immediately.
   - A rerun of a failed block needs a documented reason and a new isolation salt, and the failed block is kept as
     invalid.
   - **At most one rerun per block.** A second failure stops the stage for owner review. No automatic retry loops.
3. **Server restart.** A restart mid-stage stops the stage. Resuming starts a new server-start series, and whole blocks
   are rerun with new salts.
4. **Fixed sample size.** n = 10 per cell; no seeds are added or dropped after any look at outcomes.
5. **Noise floor.** If A/A-ind at some (C, L) is not Vb, that level is reported as E∧¬Vb and excluded from the primary
   stratum. The run still completes.
6. **Budget.** If cumulative wall time exceeds 1.3× the stage estimate, stop and report.
7. **Stage order and approval.** Each of P, S, A and B needs **separate** owner approval. Stage A runs only after S
   passes. Stage B runs only if every Stage A block is valid.
8. **Interpretation boundary.** Differences between caps or paths are reported as admission or batching effects of the
   execution path, never as isolated gateway software overhead and never as GPU-only effects.

### 9.1 Loader operational choices (item 8; written before any v5 data, for owner review before the freeze)

The §3–§6 text left these open. `scripts/v5_analysis.py` fixes them as follows:

1. **Non-evaluable hypotheses in a Holm family.** The family size stays fixed (F1 = 3, F2 = 3). A non-evaluable
   member enters with p = 1, so it cannot be rejected and cannot make the others easier to reject. It is reported as
   **not evaluable**.
2. **Evaluability.**
   - H1, H2a, H2b and H6 need their cells in stratum E∧Vb.
   - H2a also needs identical seed lists in the three caps.
   - H3 and H4 need their cells to be E; Vb is not required, because they are mechanism checks, not effect tests.
3. **H3 observable.** It is the same quantity the predictions were frozen on (`v5_fcfs_predictions.holds`): the
   mean of t_sent − t_offered over victims with both timestamps, without warm-up exclusion.
   - The frozen cell values are used whenever the cell holds all 10 protocol seeds.
   - Plumbing subsets recompute the cell rule over the loaded seeds and are flagged `frozen_cell_values: false`.
4. **H4(b), operationalized.** The attack-arm victim mean gateway queue (cell mean) is lower at C = 32 than at C = 8,
   **and** the H3 score for D vs S, L = 200, attack arm passes at both C = 16 and C = 32.
5. **H4(c).** The verdict uses the gateway arms (C = 8, 16, 32), both arms of every seed. The direct-path arms are
   scored and reported, but descriptively only.
6. **H5.** "Saturation" uses each arm's **own** cap C, not the v4 reference cap of 8. That means the fraction of the
   window with k ≥ C, and the fraction of victims arriving while k ≥ C. The computation uses the frozen slot-time
   primitives (`occupancy_steps`, `time_weighted`, `k_at`).
7. **Threshold validity** is evaluated against the A/A-ind cell at the same (C, L). D vs S at L = 400 on the direct
   path has no A/A-ind reference, so it reports `null`.
8. **No interim looks (§6), enforced.** On real data the loader refuses an incomplete stage before computing any
   endpoint. Only an all-synthetic (mock) input may be incomplete. It also refuses to overwrite an existing analysis
   without `--force`.

Items 8–11 must not change any frozen artifact. A test pinning the frozen files' SHA-256 values is added **in freeze commit 1** itself
(it cannot be pinned before the files are frozen).

## 12. Scope boundary

This remains attack-side characterization:
- no defenses, RL or scheduler contributions;
- private owned target only;
- synthetic tenants and prompts.

The cap is varied to characterize how a fixed, authorized token budget converts into victim harm under different
admission configurations. It is not tuned as a mitigation.
