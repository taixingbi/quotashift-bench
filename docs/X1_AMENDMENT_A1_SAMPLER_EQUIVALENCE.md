## 2. Why the rev 4 rule cannot work as a qualification gate

The rev 4 rule compares two nearest-rank medians of 20 requests each and fails if |Δ| > 1 ms and > 2%. Request-level
idle TTFT on gpu-node-2 has sd 4.26 ms (MAD 2.29 ms) even after excluding the first request of each pass. The median
of 20 such values moves by several ms between repetitions.

| Quantity | Value |
|---|---|
| P(rule FAILS \| no sampler effect), simulation, attempt-2 noise | **0.530** (0.555 when first-request outliers are kept) |
| Same, permutation of attempt 2's 40 values | 0.477 |
| Bootstrap 95% interval of attempt 2's Δ | −2.6 to +4.9 ms |
| P(rule PASSES) at a true shift of 0 / 0.5 / 0.9 / 1.5 ms (simulation, 20,000 draws) | 0.468 / 0.477 / 0.448 / **0.363** |

The rule is a coin flip with no defined error rate. It cannot tell "no effect" from "effect of 1 ms". It passes a real
0.9 ms shift about as often as no shift, and passes a 1.5 ms shift, which is beyond the tolerance, 36% of the time. The tolerance it encodes, max(1 ms, 2%), is reasonable. The
decision procedure is the defect.

## 3. Proposed amendment text (exact; becomes `docs/PROTOCOL_X1_AMENDMENT_A1.md` on approval)

> **Protocol X1, Amendment A1: sampler on/off equivalence (post hoc, 2026-11-25).**
> This amendment was written after two g0m0 Phase 1 attempts failed under the rev 4 point-estimate rule. Both FAIL
> verdicts stand. A1 replaces, for every X1 Phase 1 preflight run that starts after A1 is pinned
> (`experiments/x1/AMENDMENT_A1_SHA256.json`), the §9.1 row "Sampler on/off equivalence". It applies identically to all
> four platforms. Everything else in rev 4 is unchanged.
>
> **A1.1 Question and tolerance.** Is the median idle TTFT with the host sampler running within ±δ of the median with
> it stopped? δ = max(1 ms, 2% × the nearest-rank median of all measured OFF requests). This is the rev 4 tolerance,
> unchanged.
>
> **A1.2 Design (fixed sample size).**
> - **Pairs:** K = 24 pairs of segments, 48 segments in all. Pair k (0-based) runs OFF then ON if k is even, and ON then OFF if k is odd. Each arm comes first in 12 pairs, and both arms have the same mean position, so a linear drift cancels.
> - **Each segment, in order:**
>   1. Set the sampler state and verify it. ON: the frozen `scripts/x1_host_sampler.py` is running in daemon mode, unchanged, at 1 Hz and nice 19. OFF: no sampler process.
>   2. Verified `/reset_prefix_cache`, i.e. the frozen `reset_and_verify` probe shows warm hits before the reset and zero after.
>   3. W = 3 warm-up requests on dedicated prompts (seeds 900–902). These are recorded but never analysed.
>   4. M = 80 measured requests on one fixed prompt list (`prompt_of(60, seed)`, seeds 200–279, `max_tokens` 8, temperature 0, `ignore_eos`, streamed). The list is **identical in every segment**.
>   5. ON only: verify the sampler is still running, then stop it and verify that no sampler process remains.
> - **Request discipline:** one request in flight, sent back-to-back, with a fresh HTTP connection each.
> - **Timing:** TTFT is measured on the runner (monotonic clock, send to first non-empty text chunk), independently of the GPU-host sampler.
> - **Recorded per request:** wall-clock send time, TTFT, end time, segment, arm and prompt seed.
> - **Recorded per segment, for the record only:** the server's `vllm:time_to_first_token_seconds` histogram sum and count, before and after.
>
> **A1.3 Statistic.** For each pair, d_k = p50(ON_k) − p50(OFF_k), using the frozen nearest-rank `pctl` over the 80
> measured requests. D̄ = mean d_k; SE = sd(d_k)/√K; df = K − 1 = 23.
>
> **A1.4 Decision (TOST, α = 0.05).** PASS iff the 90% two-sided interval D̄ ± t₀.₉₅,₂₃ · SE (t = 1.713872) lies strictly
> inside (−δ, +δ). Otherwise FAIL. Also FAIL if any of the following holds; there is no flag outcome:
> - a segment is missing, or does not have exactly 80 finite measured TTFTs;
> - a reset was not verified;
> - the sampler state was not verified.
>
> The 95% interval and the rev 4 point rule (applied to the pooled requests) are reported alongside, and do not decide.
>
> **A1.5 Unchanged.**
> - `sampler_overhead` stays exactly as frozen: the sampler's own CPU must be < 1% of a core. It is measured, as in attempt 2, by a dedicated finite 65 s sampler run that writes its summary.
> - Every other Phase 1 and Phase 2 gate, threshold, seed, hypothesis, family, prediction and analysis rule in rev 4 is unchanged.
> - The idle TTFT floor remains descriptive. It is reported as the nearest-rank median of the measured OFF requests.
>
> **A1.6 One run, no retries.** The first amended run per platform is final. On g0m0, one amended Phase 1 run needs its
> own owner token. If A1 or any other Phase 1 gate fails, the platform is not admissible and the stage stops; there is
> no further attempt.

## 4. TOST (90%) vs the strict 95% interval

Both use the same design and statistic. "Strict 95%" requires the 95% interval inside ±δ, which is TOST at α = 0.025.

| | TOST 90% (proposed) | Strict 95% |
|---|---|---|
| P(pass \| true shift = ±δ): test size, all 27 scenarios, at K = 24, M = 80 | 0.041–0.054 (nominal 0.05) | 0.014–0.027 (nominal 0.025) |
| Same, at K = 40, M = 60 | 0.047–0.056 | 0.021–0.028 |
| Smallest fixed design meeting C1 + C2 (§5) | **K = 24, M = 80**: 1,920 per arm, ≈ 18 min on G0 | K = 40, M = 60: 2,400 per arm, ≈ 24 min on G0 |
| Power at θ = 0, base / pessimistic, at its own design | 0.997 / 0.828 | 0.998 / 0.854 |
| Power at θ = 0, base / pessimistic, at K = 24, M = 80 | 0.997 / 0.828 | 0.992 / 0.680 |

The grid in §5 and this sensitivity table are independent 4,000-draw estimates (MC SE ≈ 0.006), so the same cell
can differ slightly. For example, the pessimistic power at K = 24, M = 80 is 0.816 in the grid and 0.828 here.

**Recommendation: TOST at α = 0.05**, for four reasons:
- It is the standard equivalence test (Schuirmann), and its interval is the conventional one for a 5% equivalence claim.
- The consequence of a false pass is bounded. The sampler runs identically in the attack and control arms of every block, so any residual shift below δ is common-mode (§7).
- Strict 95% costs about 6 more minutes per platform for less power at equal n.
- **Owner's choice:** strict 95% at K = 40, M = 60 is fully specified and costed if you prefer it. The amendment text then changes only K, M, t and "90%" → "95%".

## 5. Sample-size justification (prospective, fixed)

**Noise model.** Attempt 2's 40 cache-cold idle TTFTs (gpu-node-2, Qwen, vLLM 0.17.1). Each arm is centred on its own
median, so the observed +1.23 ms is not carried into the null. Residuals are resampled with replacement.
- **"clean" pool:** without the first request of each pass, which the warm-up requests absorb. sd 4.26 ms, MAD 2.29 ms.
- **"tail" pool:** keeps those two ~48 ms first-request outliers, as a stress case in which warm-up fails.

**Sensitivity axes:**

| Axis | Values |
|---|---|
| Noise scale | × 1, 1.5, 2 (G1, a 4-vCPU host, may be noisier) |
| Segment-level random offset sd | 0, 0.25, 0.5, 1.0 ms (drift between segments, independent per segment: a worst case for pairing) |
| Linear drift | 0.05 ms per segment (2.4 ms over the session) |
| Baseline | 50 ms (δ = 1.0 ms floor: sizing case) and 58 ms (G0 observed, δ ≈ 1.16) |
| True shift θ | 0, 0.25δ, 0.5δ, ±δ |
| Draws | 4,000 per power cell; 20,000 per size cell (MC SE ≈ 0.0015) |

**Selection criteria**, written in the script before its first run:

| Criterion | Requirement |
|---|---|
| C1 | power ≥ 0.95 at θ = 0, base: clean, × 1, offset 0.25 ms, δ = 1.0 |
| C2 | power ≥ 0.80 at θ = 0, pessimistic: × 1.5, offset 0.5 ms, δ = 1.0 |
| C3 | size ≤ α at ±δ in all scenarios |
| Tie-break | smallest 2·K·M, then smallest K; grid K ∈ {8 … 48} even, M ∈ {20, 30, 40, 60, 80} |

**Two corrections before the final run** (both in the log):
1. The grid was extended so that the strict 95% option could also meet C1 + C2.
2. For the drift scenario, the boundary θ is now the rule's own δ at the session-mean baseline. Drift raises the OFF median, so δ rises to about 1.03 ms, and testing at θ = 1.00 had overstated the size.

**Grid excerpt** (power at θ = 0, TOST, base / pessimistic):

| K × M | per arm | G0 min | base | pess |
|---|---|---|---|---|
| **10 × 30** (≈ "300 per pass") | 300 | 3.8 | **0.24** | **0.02** |
| 16 × 60 | 960 | 9.7 | 0.89 | 0.36 |
| 20 × 60 | 1,200 | 12.1 | 0.96 | 0.53 |
| **24 × 80 (chosen)** | 1,920 | 18.2 | **0.998** | **0.816** |
| 32 × 60 (same n) | 1,920 | 19.4 | 0.998 | 0.840 |
| 40 × 60 | 2,400 | 24.3 | 1.000 | 0.923 |

**300 requests per pass is not sufficient.** It has power 0.24 even in the base case: the gate would usually fail with
no sampler effect at all. My earlier estimate of about 300 was wrong.

**Sensitivity at the chosen design** (K = 24, M = 80, TOST):

| Scenario | P(pass \| 0) | P(pass \| 0.25δ) | P(pass \| 0.5δ) | Size at +δ / −δ |
|---|---|---|---|---|
| base, δ = 1.0 | 0.997 | 0.965 | 0.751 | 0.052 / 0.049 |
| base, G0 baseline 58 ms | 1.000 | 0.992 | 0.852 | 0.051 / 0.047 |
| offset 0.5 ms | 0.982 | 0.916 | 0.643 | 0.051 / 0.049 |
| offset 1.0 ms | 0.758 | 0.641 | 0.402 | 0.049 / 0.053 |
| noise × 1.5, offset 0.5 (pessimistic) | 0.828 | 0.711 | 0.450 | 0.050 / 0.049 |
| noise × 2, offset 0.5 | 0.510 | 0.462 | 0.299 | 0.050 / 0.050 |
| linear drift 0.05 ms/segment | 0.997 | 0.970 | 0.767 | 0.051 / 0.047 |
| tail pool (warm-up fails) | 0.989 | 0.940 | 0.697 | 0.051 / 0.050 |
| tail, × 1.5, offset 0.5 | 0.711 | 0.609 | 0.389 | 0.053 / 0.054 |

**Readings:**
- **Size** stays at the nominal 5% across every scenario (0.041–0.054; the maximum is in the tail stress case, about 3 MC SE above 0.05).
- **Pairing is necessary.** On the same draws, a naive analysis that pools all requests and ignores segments has size up to **0.238** under segment offsets.
- **Power** is high at G0-like noise. It degrades if a platform's idle TTFT is ≥ 1.5–2× noisier or drifts between segments by ≥ 1 ms: power 0.51–0.83 there.

**Limits of this justification:**
- It rests on 38–40 observations from one host and session. The median's sampling variance depends on the density near the median, which 38 points estimate poorly; the × 1.5 and × 2 axes cover this.
- The simulation draws requests independently within a segment. Autocorrelation within a segment would widen sd(d_k). The pair-level interval then absorbs it in the estimate, but power falls.

**Duration:** 2·24·(80 + 3) requests × 0.23 s, plus 48 resets and 24 sampler toggles, ≈ **18 min** on G0. The full
amended Phase 1 is ≈ 25 min of gpu-node-2 time.

## 7. Effect on X1's statistical interpretation; Threats to Validity

**What does not change:**
- H1–H6, the 1.25 threshold, the Holm families F-X1 and F-X2, seeds, predictions, the verdict rule and every analysis script.
- The gate is a host-instrumentation qualification. It enters no test statistic.

**What changes:**
- **Admissibility now needs positive evidence.** Under rev 4, a platform was admitted with about 47% probability whatever the truth, including a real 0.9 ms sampler effect. Under A1, a platform is admitted only with evidence that |shift| < δ, with a 5% false-admission rate at |shift| = δ.
- **Shared rule:** all four platforms use the same rule.

**Threats to validity:**

1. **Post-hoc amendment.** A1 was written after two failures of the anchor platform, so there is a forking-paths risk.
   - **What limits it:**
     - The tolerance δ is the rev 4 value, unchanged.
     - Design, n and selection criteria were fixed in code before the simulation's first run, using no outcome data beyond attempt 2's noise.
     - A1 applies to every platform, including those not yet run.
     - Both failures are preserved and reported.
     - One run, no retries.
   - **What remains:** a reader cannot verify that a different amendment would not have been chosen had attempt 2 passed. The paper must report the amendment, its date and both failures.
2. **Idle-only check.** A1 bounds the sampler's effect on **idle** TTFT only. Interference under load (CPU contention between the 1 Hz sampler and the API server's event loop) is not measured.
   - **Mitigation:** the sampler measured 0.05% of a core; it runs in **both arms** of every block, so its effect is common-mode and largely cancels in attack/control ratios; a ≤ δ additive shift (≈ 1.7% of idle TTFT) cannot create or hide a 1.25× ratio.
   - Not formally tested.
3. **Power is platform-dependent.** n was sized on G0 noise. A noisier platform (the 4-vCPU g6.xlarge in G1) could fail A1 for lack of power, not because of a sampler effect, and would then be not admissible.
   - That would count against the GENERALISES verdict (≥ 3 of 4 platforms) for an instrumentation reason.
   - Power is 0.83 at 1.5× noise and 0.51 at 2× noise with 0.5 ms segment drift.
   - Such an exclusion must be reported as "inconclusive equivalence", not as "the sampler perturbs".
4. **Noise model from one session.** 38–40 observations of one host and model. The 1.5× and 2× scales bracket it; they do not replace measurement.
5. **Time cost.** The amended Phase 1 takes ≈ 25 min instead of ≈ 7 min per platform. On G1 this is extra instance time, costed against the existing cap.
